### Claude:

The idea works. Origin Shift is a spanning tree sampler for any graph, and the ring of a shaft segment is a graph. Determinism is not a problem. You seed a generator with the world seed, the shaft id and the segment index. You start from a fixed tree, for example every node points along the shaft axis toward the root. You run a fixed step count. The result is a pure function of those three values, so chunk order does not matter. Two findings matter before a prototype.

**The one-root layout makes a seam.** With node cells on odd blocks and edge cells on even blocks, the ring at block 0 of every chunk holds only crossing edges. One root in the next segment means one crossing. So every 16 blocks a full wall ring with one gap circles the shaft. It reads as a repeating bulkhead, not as a maze. Decay hides it in the regions where decay removes walls. It stays visible everywhere else. Origin Shift does not cause this. Any scheme with one tree per chunk and one bridge per boundary causes it.

**Two segment types remove the seam.** Alternate "tree" segments and "connector" segments along the shaft. A tree segment is a plain spanning tree of its own nodes with no crossings. A connector segment is a spanning tree of its own nodes plus two virtual nodes. The left virtual node touches every node of the left ring. The right virtual node touches every node of the right ring. Replace each virtual node with the neighbor tree segment. The union is one spanning tree of the whole infinite shaft. The proof is the standard contraction argument. The two virtual nodes get several tree edges each, so each boundary has several gaps. A chunk needs at most two segment computations: its own, and the connector on its left. Both are pure functions of the seed and the index. The scheme has no preferred direction.

**Facts about Origin Shift for the prototype:**

- The stationary distribution, conditional on the root, is uniform over spanning trees. This holds for the connector graph too, because every non-root node contributes one factor of one over its degree. Wilson's algorithm samples that same distribution exactly, in finite time, with no step count. The prototype can compare the two.
- From a fixed start tree, the chain needs many multiples of the random walk cover time before the tree looks random. The step count is a tuning value. The prototype measures it with dead-end counts and edge frequencies.
- The cost is small. The ring has 24 nodes and a chunk has 8 node rows, so a segment has 192 nodes. A few tens of thousands of steps per segment is cheap.
- A column is finite. One run over its whole surface covers it, since the chunk generates the full height at once. The junction boxes cut holes in the surface graph.

**One CLAUDE.md conflict.** The Shafts section says the maze comes from Markov rewrite rules and that the prototype tries rule sets. Origin Shift has no rule set. Its parameters are the segment lengths, the start tree and the step count. The project file needs that wording changed once you settle the design. I did not change it.
