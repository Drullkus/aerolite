 * The erosion resistance of shaft and junction box blocks, from 0 at a surface to 1 at a core.
 *
 * <p>Written by Claude Code; conversation transcript: {@code llm/transcripts/transcript_2026-10-29_20-21_80fbac8f-2f3a-4fd7-813a-624e3db43bca.md}.

@Component
public final class ErosionResistance {

    /** The resistance of a box block. It is the largest of the box resistance and the resistance of each shaft through the block. */
    public double box(ColumnJunction junction, int dx, int dy, int dz) {
        double box = (double) (Ring.BOX - Math.max(Math.abs(dx), Math.max(Math.abs(dy), Math.abs(dz)))) / (Ring.BOX - 1);
        double column = this.section(dx, dz);
        double horizontal = junction.alongX() ? this.section(dy, dz) : this.section(dy, dx);
        return Math.max(box, Math.max(column, horizontal));

    public double section(int first, int second) {
        int offset = Math.max(Math.abs(first), Math.abs(second));
        return offset > Ring.OUTER ? 0 : Math.min(1, (double) (Ring.OUTER - offset) / (Ring.OUTER - 1));
    }

**Statics moved into components**
- **Maze math:** `Ring` is a component. Its constants stay static. The edge collection moved into a new `MazeEdges` component.
- **Maze factory:** a new `ShaftMazes` component makes each maze.
- **Box math:** a record cannot hold an `@Autowired` field. So the `Box` methods that need `Ring` are now `ShaftMaze` methods.
- **Shaft painting:** `ShaftPainter`, `MazeCarver`, `ShaftFrames` and `ErosionResistance` are components. The state of one chunk moved into a new `ChunkPaint` class.
- **Chunk status:** the mutable status field is gone. Both mixins and the `AeroliteChunkStatuses` component read the status from the chunk status registry. The mixins run before `BeanContext.init`, so they cannot use a component.
- **Registration and events:** `AeroliteWorldgen`, `AeroliteClient` and `AeroliteDataGenerators` are components. Each one adds its listeners to the mod bus in a `@PostConstruct` method. The client slider math is in a `PresetSliders` component.
- **Datagen entries:** the worldgen entries are in a new `AeroliteWorldgenEntries` component. The provider calls `super(...)` before it can use its own methods, so the entries had to move out of it.

**Injection.** I used `@Configurable` fields only on the chunk generator. `BeanContext.injectInto` is `synchronized` and scans every `@Autowired` annotation on each call. So objects that worldgen makes per chunk or per segment take their components through their constructors. GameTest methods are static, so `ShaftGameTests` gets its components through static `@Autowired` fields.

**WorldEdit**
- Version 7.3.8 comes from the EngineHub maven, as `worldedit-neoforge-mc1.21`. It loads in the dev runs only, and the production jar does not hold it.
- That mod jar does not contain the WorldEdit core. So the core goes into `additionalRuntimeClasspath`, and the game layer loads it as a library.
- I excluded Guava, Gson, fastutil and Log4j from the core. WorldEdit asks for a Guava version that conflicts with the version that Minecraft pins.

**CLAUDE.md** has new rules that make components preferred over statics. It also has a new WorldEdit section.
