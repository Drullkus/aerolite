I fixed the tests. They now use fixed test data, so a change to the production defaults can't break them again. All 43 JUnit tests and all 7 GameTests pass. `./gradlew build` succeeds, and `runData` changes no generated file. I didn't start the client or the dedicated server, because no production code changed.

**What broke:** two tests in `AeroliteSettingsTest` assumed the old default lists. The Nether list had one variation and the Overworld list had two.

**The fix:**
- **New fixture:** [TestSettings.java](src/test/java/us/drullk/aerolite/world/TestSettings.java) holds a fixed `SETTINGS` and four fixed variations: `STONE`, `TUFF`, `NETHER` and `END`. It uses the defaults from before `3b3eb19`, so seeded tests such as the column and erosion searches still pass.
- **Settings, layout and GameTests:** `AeroliteSettingsTest`, `ShaftLayoutTest` and `ShaftGameTests` now use the fixture. They no longer use `AeroliteSettings.DEFAULT` or the `ShaftVariation` constants.
- **`unlistedDimensionGetsNoShafts`:** this test still takes the generator from the preset. It now gives that generator the fixture settings, so it doesn't depend on the preset's variation map.
- **`erosionStaysAboveTheDecayThresholdOfAnOldSave`:** this test now sets the erosion threshold in its JSON. Before, it depended on the default value.
- **`cloudHeightDefaultsToMinus32`:** I removed this test. It only checked a production value.
- **`variationEditsReturnNewSettings`:** this test checks again that an edit leaves the original settings unchanged. Your commit had removed that check.

**What still reads production data, on purpose:**
- **Codec fallback tests:** these compare the codec's fallback with `DEFAULT` itself. They pass for any default values.
- **`defaultListOfAnotherDimensionIsStoneWithWeightOne`:** this test checks the rule that an unlisted dimension gets stone with weight 1.
- **`presetIsNormalAndBuildsShafts`:** this test checks that the real preset builds shafts in the Overworld. It fails only if the preset's Overworld has no variations.
