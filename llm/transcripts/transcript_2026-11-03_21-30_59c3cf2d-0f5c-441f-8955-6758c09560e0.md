### Claude:

Here is the batch plan. Each batch is one Opus subagent in its own worktree on a `claude/java-*` branch. Inside a wave no two batches edit the same file. A wave starts after you merge the wave before it.

**Wave 1, two agents**

- **J0a Settings model**, branch `claude/java-settings-model`. Adds the pattern, the shape, the Surface provider and the Trusses provider to the variation record. The pattern is a dispatch codec over a sealed settings hierarchy with every type registered now: Mazes with type, strength, seam and spacing; Bricks, Tiles, Scales and Chaos with their options plus the shared fields allow loops (on), loop share (50%), surface paths (off), cutting (off) and path chance (75%). Chaos spacing is 6 to 12. Defaults load a 0.3 save unchanged. Updates equality, the world pillar pack, datagen, the settings JSON and the JSON tests. No paint, no screens.
- **J0c Surface path library**, branch `claude/java-surface-paths`. Ports the shared Python module as pure logic in a new package with JUnit tests that mirror the prototype checks. Its band type carries a ring length, so the I-beam and Bridge rings fit. Fixes the three gaps once: several components per chunk, edges longer than one chunk, and the orphan and face width checks.

**Wave 2, two agents**

- **J0b Surface model**, branch `claude/java-surface-model`. Introduces the ring description with corner kinds, floors and crossing candidates, the per-segment band that the chunk paint consumes, the pattern interface, and the binding components that a Directory list collects. The maze becomes the first pattern. The sampler gains spanning forests, the foreign-patch virtual node hook and the rule that a node carves only with an edge. Settings without a binding fall back to the Uniform maze with one log line. The fingerprint test and every maze test and GameTest pass unchanged.
