### Claude:

The Aether now gets its own 128-256 spacing and a column chance of 0.7. A client run read those values from the data pack, through a temporary log line that I removed after the run.

**Cause:** [AeroliteWorldgenProvider.java](src/datagen/java/us/drullk/aerolite/datagen/AeroliteWorldgenProvider.java) wrote only the namespaces `aerolite` and `minecraft`. Data generation dropped your `aether:the_aether` placement with no error, so the dimension took `aerolite:default`, which is 48-80.

**Fix:** The provider now also writes the namespace of each key of `ShaftRegistries.DIMENSION_LISTS`. Your next prefabs need no provider change if their dimension is in that map. This also adds `data/aether/aerolite/shaft_placement/the_aether.json`, a regression test and two facts in `CLAUDE.md`.

Apply the branch to `main`:

```bash
git cherry-pick -n main..claude/modded-placements
```

A world that was created before this fix keeps 48-80, because the save holds its settings. In the pillars screen, a configured Aether row also keeps its copied values. Remove the row and add it again, or use a new world.

## When you add the next prefabs

Add one line for each mod in `AeroliteShaftEntries#conditions`, with the list and every variation that use its blocks:

```java
needsMod(conditions, "twilightforest", ShaftRegistries.TWILIGHT_LIST, TWILIGHT_STONE);
```

`TWILIGHT_STONE` is an example name. If you forget a line, `runGameTestServer` stops at the registry load, because that server does not load the dimension mods.

Run `runData` after each change. Also add the dimension to `DIMENSION_LISTS` if it is not there, so that its placement gets written. Bumblezone, Gaia, Twilight Forest and Voidscape are already there.
