# Plan: Voronoi preview fixes

## What the code does now

- [PreviewRenderer.java:414](src/main/java/us/drullk/aerolite/client/preview/PreviewRenderer.java:414) draws the cell lines in two passes. The first pass draws the parts behind blocks at 30% opacity.
- That first pass sets `depthMask(false)`. The render type `lines` does not restore the depth mask, so the value leaks.
- After the leak, no cell line writes depth. The floor grid draws last, so it draws over every cell line. This is the likely cause of the picture. Batch A confirms it in a run first.
- [PreviewScreen.java:507](src/main/java/us/drullk/aerolite/client/preview/PreviewScreen.java:507) `pickCell` calls `pan.set(site.x, site.z)`. This is the unwanted move.
- A lattice key rule decides which cell draws a shared face. The hovered cell draws last to cover the other cells.

## Batch A: render (one subagent)

Files: `PreviewRenderer.java`, `CellGeometry.java`, `CellGeometryTest.java`.

1. **Depth order.** Delete the pass behind blocks and the constant `CELL_COVERED_ALPHA`. Cell lines, floor grid and region outline draw with the plain depth test and depth write. No depth state leaks.
2. **Blocks hide every cell line.** This follows from step 1. Edges, site crosses and gridlines all hide behind blocks.
3. **Back-face test.** A face draws its gridlines only when `face.distance(camera) > 0`. A nearer face hides nothing.
4. **Shared faces.** The back-face test picks exactly one of the two cells. The lattice key rule and the `drawn` set go away. The gridlines are gold when either cell is the hovered cell.
5. **Fade.** `CellGeometry.Face` gets one method: the distance from a point to the nearest edge of that face. The renderer cuts each gridline into short pieces. Each vertex takes the opacity `0.35 * (1 - smoothstep(0, 32, distance))`. A piece fully beyond 32 blocks draws nothing.
6. `Face.gridlines()` keeps its type. So the probe check and the old tests stay valid.
7. New JUnit tests check the edge distance on a box face and on a tilted face.

Result: one cell pass, not two. The class loses the dedupe rule and the depth state overrides.

## Batch B: click (one subagent)

Files: `PreviewScreen.java`, `IslandsProbe.java`.

1. `pickCell` no longer moves the region center.
2. `pickCell` adds every chunk of the cell to the picked set.
3. A shift no longer removes picked chunks outside the region. The builder already skips them. A later pan generates each picked chunk that enters the region.
4. A scene change still clears the picked set.
5. The chunk sequence stays nearest the region center first. `PreviewBuilder` does not change.
6. The probe check after the click changes. It states that the region center did not move and that the picked set equals the cell chunks.

## What changed

- **Grid draw order.** The cause is confirmed in the vanilla sources. The old pass behind blocks set `depthMask(false)`, and the render type `lines` never restores it. The cell lines now draw in one pass with the plain depth test.
- **Blocks hide every cell line.** The faint pass behind blocks and its opacity constant are gone.
- **Back-face test.** A face draws its gridlines only when its outer side faces the camera. The lattice key rule for shared faces is gone.
- **Fade.** The gridline opacity falls along a smoothstep curve to zero at 32 blocks from the nearest face edge. `CellGeometry.Face.edgeDistance` gives the distance, with two new JUnit tests.
- **Click.** A click picks every chunk of the cell and does not move the region center. The chunk sequence stays nearest the region center first.
- **Probe.** The probe now fails if the click moves the region center. It then moves the center itself to frame the cell for its screenshots.
- **`CLAUDE.md`.** The cell bullets under Islands state the new rules.

`PreviewRenderer.java` is about the same size as before. The fade code replaces the removed two-pass code.

## What I checked by eye

The probe screenshots show the fade, the back-face rule, gold gridlines on the hovered cell and terrain that hides the lines behind it. The probe has no top or bottom view at far zoom, so the exact view of your picture is not checked.
