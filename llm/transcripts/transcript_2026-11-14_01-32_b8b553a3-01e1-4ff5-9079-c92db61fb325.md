## Prompt 1 — 2026-11-14 01:32:43 UTC

### User:

Create a technical plan for Opus subagents to use, it shall go on my approval.

It's time to create the island types. The goal is to provide me with tools creating my own island types that will become prefabs. Sky island instances come in varieties, like Pillars do.

Each island variation dispatches its own Density Function and Biome Source. Empty becomes an island variation. Island variations are chosen via weighted list in generation. An island variation can be a weighted sub-list of island variations.

All current sliders get taken by island variations, besides jitter and separation of pre-jitter cell sites. The plan stays that only one layer of voronoi cells generate islands, with sites above and below generating empty, only to influence generation of cells in that middle layer.

Per-variation island cell sizes become weights, defaulting to 0.5 and operates by fractional values [0.0..1.0]. They become distance multipliers for choosing which blockpos goes to each cell, where the higher weight causes a cell to take more space from cells with lesser weight. This uses min-max sliders and the weight is chosen per variation instance.

## What the check subagent fixed

- The first checks worked only in scaled space, so they could not catch a wrong Y scale or a wrong island body. A new check compares every value in blocks. It caught 7 mutations that the first checks missed.
- `tables.json` gave an island body for a cell outside the island row. Each site now has a row, and the body is null there.
- The shader rolled the cell weight and the fill from one salt. Each roll now has its own salt.

## Findings for you

- **Lost cells:** at a cell weight range of 0 to 1 and the shipped jitter of 80%, 14.6% of the island cells lose their site. By R27 they hold no island. At a range of 0.25 to 0.75 the share is 3.5%. At equal weights it is 0%.
- **Wall reach:** the proven wall reach covers 484 lattice boxes at jitter 0.8. My reading for batch 1: the Java code keeps a proven bound and tightens it with the weight spread of the list. It uses no bound that only a sample supports.
- **Hash functions:** the prototype uses two published hash functions, lowbias32 in Python and pcg3d in the shader. They are not code of a mod. The Java code uses the vanilla mixer and does not read them. Tell me if you want them replaced.
